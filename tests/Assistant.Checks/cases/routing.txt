# Which part of the assistant answers a message.
#
# One check per line:   expected route | the message
# Lines starting with # are comments. A line starting with @ changes the setup for the checks after it:
#   @ normal       cloud chat connected, local model on
#   @ cloud-down   cloud chat connected but not answering
#   @ no-cloud     no cloud key
#   @ lite         Lite mode (no local model)
#   @ game         game mode (cloud only)
#
# Routes:
#   quick_answer, shortcut, conversation_log, organizer, action    answered by code
#   tool:search_files, tool:recall, tool:remember, ...             sent straight to a tool, no model
#   memory          answered from saved facts ("Look it up" under it)
#   cloud           cloud chat, nothing looked up
#   cloud+lookup    cloud chat with a Wikipedia lookup
#   local>cloud     the local model saw it first (something private in it), then cloud chat answered
#   local           the local model answered
#   no_answer       cloud chat was needed and didn't answer ("Try again")
#   help            a pointer to what works (Lite and game mode)
#
# The saved facts these checks use are in cases\memory. Nothing here calls a real model or the internet.
# Found a message the assistant handled wrongly? Add a line for it here, then fix the rule until it passes.
